# MB85RC v1.1.0

Minor release adding family metadata, cross-driver diagnostics, and stricter recovery/health behavior.

## Highlights

- Latched `OFFLINE` behavior keeps normal public I2C operations off the bus until `recover()` succeeds.
- Public MB85RC family variant metadata describes known capacity, address model, Device ID, high-speed, and sleep-mode differences.
- Cross-driver diagnostics gained `driverState()` and a value-returning `getSettings()` overload.
- Recovery and validation paths keep health counters aligned with transport failures and Device ID mismatches.

## Included In This Release

### Added
- `VariantInfo`, `AddressModel`, `KNOWN_VARIANTS`, `VARIANT_COUNT`, and `findVariantByProductId()`.
- `driverState()` alias for diagnostic tooling that expects a common state accessor name.
- Value-returning `SettingsSnapshot getSettings() const` overload.
- Native tests for latched `OFFLINE` behavior and recovery mismatch accounting.

### Changed
- `OFFLINE` is latched: normal memory and Device ID operations return `BUSY` without touching I2C until explicit recovery succeeds.
- Recovery bypass internals share the `ScopedOfflineI2cAllowance` / `_reassertOfflineLatch()` procedure.
- Documentation describes validation behavior for null buffers, zero-length transfers, out-of-range addresses, and current-address tracking.

### Fixed
- `recover()` now records Device ID mismatches in health tracking.
- Health updates ignore `IN_PROGRESS` statuses.
