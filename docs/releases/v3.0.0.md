# MB85RC v3.0.0

Major release expanding runtime support from the 64TA/256V pair to every
locally documented MB85RC variant. The API now uses 32-bit memory addresses so
the 1 Mbit device can be accessed without truncation.

## Highlights

- `DeviceVariant` now includes `MB85RC04V`, `MB85RC16V`, `MB85RC64TA`,
  `MB85RC256V`, `MB85RC512T`, and `MB85RC1MT`.
- `AUTO` selects Device-ID-capable variants by Product ID: 04V, 64TA, 256V,
  512T, and 1MT.
- `MB85RC16V` is supported when explicitly selected. It has no Device ID
  command, so begin/probe/recover use a safe memory-read presence check.
- Memory operations and `maxAddress()` use `uint32_t` addresses.
- Address encoding is centralized for:
  - one-byte address variants with upper address bits in the I2C address
  - two-byte address variants with A2/A1/A0 device address pins
  - MB85RC1MT transactions with A16 in the I2C address
- Shared Arduino and ESP-IDF CLI code accepts 32-bit address ranges and keeps
  the same command surface.

## Breaking Changes

- `readByte`, `read`, `writeByte`, `write`, `fill`, and `verify` now take
  `uint32_t address`.
- `maxAddress()` and `SettingsSnapshot::maxAddress/currentAddress` are now
  `uint32_t`.
- Code that stored `maxAddress()` or CLI addresses in `uint16_t` should be
  updated before using 512T or 1MT parts.

## Validation

- Native Unity tests passed with coverage for explicit begin across all
  variants, AUTO selection for Device-ID-capable variants, variant-specific
  address encoding, 1MT 32-bit current-address tracking, cross-end rejection,
  and MB85RC16V no-Device-ID diagnostics.
- Arduino PlatformIO builds passed for ESP32-S3 and ESP32-S2 examples.

Hardware-in-loop validation remains required before tagging for production use
on each physical variant.
