# MB85RC v2.0.0

Major release adding the framework-neutral ESP-IDF-ready core, shared
Arduino/ESP-IDF CLI, active-capacity runtime contract, and first-class runtime
support for every locally documented MB85RC variant.

## Highlights

- `DeviceVariant` now includes `MB85RC04V`, `MB85RC16V`, `MB85RC64TA`,
  `MB85RC256V`, `MB85RC512T`, and `MB85RC1MT`.
- `AUTO` selects Device-ID-capable variants by Product ID: 04V, 64TA, 256V,
  512T, and 1MT.
- `MB85RC16V` is supported when explicitly selected. It has no Device ID
  command, so begin/probe/recover use a safe memory-read presence check.
- Memory operations and `maxAddress()` use `uint32_t` addresses so 1 Mbit
  devices can be accessed without truncation.
- Address encoding is centralized for one-byte address variants, two-byte
  address-pin variants, and MB85RC1MT transactions with A16 in the I2C address.
- Shared Arduino and ESP-IDF CLI code accepts 32-bit address ranges and keeps
  the same command surface.
- Bulk memory operations reject cross-end ranges instead of silently relying on
  device rollover.

## Breaking Changes

- `readByte`, `read`, `writeByte`, `write`, `fill`, and `verify` now take
  `uint32_t address`.
- `maxAddress()` and `SettingsSnapshot::maxAddress/currentAddress` are now
  `uint32_t`.
- Code that stored `maxAddress()` or CLI addresses in `uint16_t` should be
  updated before using 512T or 1MT parts.

## Included In This Release

### Added
- `DeviceVariant` selector and `Config::expectedVariant`.
- Runtime accessors: `variantInfo()`, `variantName()`, `deviceId()`,
  `capacityBytes()`, and `maxAddress()`.
- Expanded `SettingsSnapshot` variant/capacity fields.
- ESP-IDF component metadata and a pure ESP-IDF `examples/espidf_basic` build
  of the full bring-up CLI.
- `examples/common/IdfArduinoCompat.h` example shim that routes the shared CLI
  through ESP-IDF v6 `i2c_master_*` APIs.
- Native coverage for explicit begin across all variants, AUTO selection,
  mismatch rejection, address encoding, active-capacity bounds, current-address
  bounds, active-variant probe/recover behavior, and no-Device-ID diagnostics.

### Changed
- `begin()`, `probe()`, and `recover()` validate the selected active runtime
  variant instead of hard-coding Product ID `0x510`.
- `read()`, `write()`, `fill()`, `verify()`, and multi-byte current-address
  reads now require the full requested range to fit inside the active runtime
  capacity.
- Example typed-memory helpers validate against `device.capacityBytes()`
  instead of the legacy 256V range.
- The CLI initializes with `DeviceVariant::AUTO` and reports active
  variant/capacity.
- `library.json`, `idf_component.yml`, README, IDF port notes, and
  Doxygen-facing comments describe the driver as an MB85RC-family driver.

### Fixed
- Active-capacity range checks compare native `size_t` lengths directly,
  preventing oversized host lengths from wrapping through a 32-bit intermediate.

## Validation

- `platformio test -e native`
- `platformio run -e esp32s3dev`
- `platformio run -e esp32s2dev`
- `python tools/check_cli_contract.py`
- `python tools/check_core_timing_guard.py`
- `python scripts/generate_version.py check`
- `doxygen Doxyfile`

Hardware-in-loop validation on real MB85RC devices is still required before
firmware teams should remove local fallback paths in production firmware.
