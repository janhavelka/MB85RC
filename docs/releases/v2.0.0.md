# MB85RC v2.0.0

Major release focused on first-class runtime variant support for MB85RC64TA and a safer active-capacity memory contract. The existing MB85RC256V default selection remains, but bulk operations no longer silently rely on device rollover.

## Highlights

- `Config::expectedVariant` selects `MB85RC256V`, `MB85RC64TA`, or `AUTO`.
- `begin()`, `probe()`, and `recover()` validate the selected active Device ID instead of hard-coding Product ID `0x510`.
- MB85RC64TA is supported as an 8 KB runtime device with Product ID `0x358`, capacity `8192`, range `0x0000..0x1FFF`, and high address-byte mask `0x1F`.
- Runtime diagnostics expose active variant metadata, cached Device ID, capacity, and max address.
- Bulk memory operations reject cross-end ranges instead of silently relying on device rollover.
- The shared Arduino/ESP-IDF CLI uses runtime capacity for full-chip scans, benchmarks, settings, and self-test output.

## Included In This Release

### Added
- `DeviceVariant` selector and `Config::expectedVariant`.
- Runtime accessors: `variantInfo()`, `variantName()`, `deviceId()`, `capacityBytes()`, and `maxAddress()`.
- Expanded `SettingsSnapshot` variant/capacity fields.
- Native coverage for 64TA begin, AUTO selection, mismatch rejection, address encoding, active-capacity bounds, current-address bounds, and active-variant probe/recover behavior.

### Changed
- `read()`, `write()`, `fill()`, `verify()`, and multi-byte current-address reads now require the full requested range to fit inside the active runtime capacity.
- Example typed-memory helpers validate against `device.capacityBytes()` instead of the legacy 256V range.
- The CLI initializes with `DeviceVariant::AUTO` and reports active variant/capacity.
- `library.json`, `idf_component.yml`, README, IDF port notes, and Doxygen-facing comments describe the driver as MB85RC-family rather than MB85RC256V-only.

### Fixed
- Active-capacity range checks compare native `size_t` lengths directly, preventing oversized host lengths from wrapping through a 32-bit intermediate.

## Validation

- `platformio run -e esp32s3dev`
- `platformio run -e esp32s2dev`
- `python tools/check_cli_contract.py`
- `python tools/check_core_timing_guard.py`

Hardware-in-loop validation on real MB85RC64TA and MB85RC256V devices is still required before firmware teams should remove local fallback paths in production firmware.
